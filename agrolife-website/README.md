# AgroLife — самостоятельный сайт, версия 0.2

Сайт написан с нуля. Он не импортирует код Android и не использует старый backend. Папку `agrolife-website` можно перенести в отдельный каталог или репозиторий.

## Запуск

Из этой папки:

```sh
python3 serve.py
```

- Сайт: http://127.0.0.1:4173
- Кабинет: http://127.0.0.1:4173/demo.html
- Другой порт: `python3 serve.py --port 4174`
- Остановка: Ctrl+C.

Для сайта нужен только Python 3. HTML, CSS и JavaScript работают без сборки. Шрифты и изображения локальные. Содержимое папки можно разместить на статическом хостинге; публичная публикация не выполнялась.

## Что изменилось в версии 0.3

В каталоге оставлены три культуры: малина, клубника и смородина. Для каждой задана цепочка от даты посадки: первичный осмотр, полив, удобрение, повторный осмотр и контроль сбора. План создаётся автоматически для каждого нового поля и попадает в «Задачи и календарь». Выбор культур хранится в профиле.

## Что изменилось в версии 0.2

**Дизайн:** Golos Text с кириллицей, основной текст 16–20 px, более крупные заголовки, контрастные подписи, удобные кнопки. На небольших экранах блоки перестраиваются, вместо уменьшения всего интерфейса.

**Целостная логика:**

1. Поле хранит название, культуру, площадь и дату посадки. Его можно добавить и редактировать. При создании можно сразу запланировать первичный осмотр: на сегодня либо на дату будущей посадки.
2. Осмотр хранит дату, фактически наблюдаемую стадию, состояние и заметку. Последнее по дате наблюдение определяет состояние поля. Осмотры в будущем и раньше посадки не допускаются.
3. Задача привязана к участку, имеет дату, время, тип и приоритет. Можно менять, переносить, завершать и возвращать её в план. При завершении сохраняется время выполнения.
4. Просрочка — незавершённая работа с датой раньше текущего дня. Обзор, календарь, карточки и помощник используют одну модель. Завершение задачи не стирает проблему, отмеченную при осмотре.
5. Полоса на карточке показывает долю выполненных задач, а не выдуманный процент роста культуры. Если осмотров нет, стадия не считается подтверждённой.
6. Календарь показывает задачи выбранного дня, просрочки или историю выполненного. Фильтр поля применяется и к списку, и к индикаторам дней.
7. Калькулятор подставляет площадь и культуру участка. При переключении га/м² площадь пересчитывается с сохранением размера участка. Изменение параметров сбрасывает старый результат. Подтверждённый расчёт можно перенести в форму задачи на полив с объёмом, площадью и нормой в названии.
8. Асыл показывает текущий план, проблемные участки и последние наблюдения по локальным сценариям. Внешняя AI-модель не подключена.
9. Имя, название хозяйства и регион редактируются в настройках. Поля, задачи, осмотры и настройки сохраняются в браузере и выгружаются в JSON.

## Данные и ограничения

Применяется текущая дата устройства. Начальные три участка и пять задач — примеры. Их даты задаются относительно первого открытия. Сохранённые задачи не сдвигаются при последующих открытиях: незавершённые работы могут стать просроченными.

Данные версии 0.1 автоматически переводятся в формат версии 2, сохраняя поля, даты и выполнение задач. Перед переносом создаётся копия предыдущей записи в localStorage. Демонстрационные проценты роста и статусы не превращаются в фактические наблюдения. Поэтому старые задачи за июнь могут появиться в просрочках — их можно перенести вручную.

При повреждении сохранённой записи исходные данные не перезаписываются. При запрете или переполнении localStorage отображается предупреждение; доступна выгрузка текущего состояния. Очистка данных браузера удаляет локальные записи. Синхронизация между вкладками и устройствами, импорт JSON и аккаунты пока не реализованы.

Прогноз погоды не подключён и не влияет на расчёты. Начальные нормы полива — условные примеры: малина 15, чеснок 8, остальные культуры 10 л/м². Пользователь должен заменить их подтверждённой нормой. Формула не учитывает почву, осадки, фазу и потери системы. Автоматических агрономических назначений нет.

Ограничения локального прототипа: до 500 полей, 2 000 задач и 3 000 осмотров. Карточка отображает последние 20 осмотров; полная история включается в выгрузку. Повторяющиеся задачи и удаление записей пока не добавлены.

```text
index.html, landing.css, landing.js   Публичный сайт

```

## Проверки

Чистая логика не требует библиотек, при наличии Node.js 18+:

```sh
node --test tests/core.test.cjs
```

Полный набор, включая DOM-проверки с Domino 2.1.6:

```sh
npm install
npm test
```

На машине разработки Node.js не установлен как CLI. Тесты выполнены через доступный JavaScript runtime: 12 проверок модели и 7 DOM-сценариев. Они покрывают расчёты, даты, миграцию, создание/редактирование, перенос и завершение задач, осмотры, сохранение, фильтрацию и сброс устаревшего расчёта. DOM-тесты подменяют отсутствующие в Domino API браузера; это не проверка реального рендеринга.

Визуальная проверка браузером остаётся ограничением: доступ к управлению браузером на компьютере отключён. Перед публичной публикацией нужны проверка реального отображения и пользовательский пилот.
